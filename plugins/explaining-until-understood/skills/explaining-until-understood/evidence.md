# 실패 유형과 수정 이력

스킬을 적용할 때 페르소나와 함께 읽고, 현재 질문과 관련된 실패를 반복하지 않는 데 쓴다. 이력을 답변에 나열할 필요는 없다.
상세 대화·실험 원자료·이전 판본 전문은 공개본에 포함하지 않는다.

## 주요 개정

아래는 각 단계의 대표적인 문제와 수정 이유만 남긴 요약이다.

| 단계 | 문제 | 수정 |
|---|---|---|
| 초기판 | 근거 없이 단정하거나, 설명이 막혀도 같은 말을 반복함 | 근거 확인·용어 정의·설명 방식 전환을 규칙으로 정리 |
| v2 | 확인 질문에 장황하게 답하고, 사용자의 형식 지시보다 예외 설명을 앞세움 | 확인형·설명형을 구분하고, 형식 지시를 우선하며 예외 조건을 제한 |
| v3 | 같은 규칙의 반복으로 핵심을 찾기 어려움 | 중복을 줄이고 공통 규칙과 페르소나를 압축 |
| v6 | 질문에 없던 목적을 붙여 다른 대상을 판정하거나, 앞 문장의 뜻을 충분히 풀지 못함 | 판정 대상 유지·대상 이름 명시·뜻풀이형을 추가 |
| v8 | 이해한 내용을 정리하는 시점과 보존할 내용이 불분명함 | 이해 확인 뒤 정리를 제안하고, 요청·승인 시 정리와 문답을 기록 |
| v9 | 정리 위치가 특정 경로에 고정됨 | 사용자가 정리 위치를 선택하고 설정으로 보존 |
| v10–v11 | 쉬운 설명을 만들면서 필요한 사실까지 빠짐 | 설명 스타일을 선택하되 사실·수치·근거는 유지하도록 명시 |
| v13 | 서로 다른 권한 주체를 같은 말로 부르거나, 권고 이유를 생략하고 질문 밖 사례로 반박함 | 대상의 층을 구분하고, 권고 이유를 설명하며 질문이 다룬 경우에서 근거·반례를 선택 |
| 공개본 정리 | 상세 대화와 실험 이력이 수정 이유를 가림 | 발화·업무 사례·상세 통계·이전 판본 전문을 빼고 실패 유형·수정 이유·검증 범위만 유지 |

## 검증 범위와 한계

- 이전 개정에서는 답변을 단발 생성해 판정 대상·형식 지시 준수·대상 이름·권고 이유 등의 표현을 비교했다. 소표본 점검이며, 사람의 이해가 개선됐다는 검증은 아니다.
- 공개용 예시로 바꾼 판본의 기존 회귀 출력 6개를 확인했다. 물은 대상에 대한 직접 판정과 대상 이름 명시, 권고 이유 포함을 점검한 범위에서 모두 통과했다. 원래 시나리오와 출력은 공개본에 포함하지 않는다.
- 모델·질문·설정이 달라져도 같은 결과가 나온다고 보장하지 않는다.
- 이번 정리는 상세 이력을 축약하고 스킬 적용 시 함께 읽도록 바꾼 변경이다. 설명 규칙의 본문은 유지했으며, 새로운 답변 생성 비교 실험은 수행하지 않았다.
